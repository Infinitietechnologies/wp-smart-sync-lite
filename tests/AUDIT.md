# SmartSync audit and regression results

Audit date: 23 October 2026. Changes apply directly to this checkout. Plugin, asset and stable versions are aligned at 1.7.1; queue schema version is 2. The project skill is maintained in `.agents/skills/smartsync-wordpress/`, with no duplicate in the user-level skills directory.

The audit reviewed maintained PHP, admin JavaScript/CSS/views, bootstrap/uninstall behavior, persisted state, provider protocols and dependency metadata. Failures found during review and execution were repaired and covered by regression tests. This is a broad local verification, not a claim that every possible environment or live cloud configuration has been proven correct.

## Dependency remediation

Production Composer dependencies and their lockfile were updated together, preserving the declared PHP 8.1 floor and regenerating Composer-managed vendor files. Minimum constraints now include AWS SDK `^3.371.4` and Google Cloud Storage `^1.51`; related authentication, HTTP and expression-parser dependencies were resolved consistently. Both production and test-tool audits reported no known advisories at the time of the final run. That describes package advisory status, not proof that the original plugin exposed every vulnerable package path.

## Practical limits

- Real cloud account permissions, provisioning/public-access policy acceptance, paid invalidations, DNS/certificate propagation and delivery through a live CDN were not exercised. SDK/HTTP protocol mocks cannot establish those outcomes.
- PHP ran on 8.3.36. The PHP 8.1 dependency solver/static target and PHP 8.0 bootstrap analysis do not substitute for executing every supported PHP/WordPress/server version.
- The browser ran in Edge on this machine. Other browser engines, assistive technologies, web-server configurations, external object-cache products and third-party plugin combinations were not exhaustively exercised.
- Bundled documentation template libraries (including Bootstrap and FontAwesome) were exercised through local page loading but were not upgraded or subjected to a separate vendor advisory audit. Composer/npm audit results apply to their tracked packages.
- Cancellation prevents later transfers and stale state writes; it cannot recall a provider request that has already started. Process/network termination can require the next worker/status poll to recover queued work.
- Single-site scans retain the existing `ABSPATH` scope, while multisite media is limited to each site's uploads. Cloud object keys remain WordPress-root-relative. Large-site throughput and production-scale memory/load testing were not established by these correctness suites.
- Uninstall does not restore media or delete cloud objects. Restore locally removed files before removing the plugin. Changing WordPress authentication salts or moving the site root requires planning for replacement of encrypted Google credentials.

No known failure from the completed checks was left unresolved. The unexecuted environments and live-service checks above remain verification boundaries, rather than passing results.
